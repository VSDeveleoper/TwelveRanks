# Twelve Ranks — Developers, Designers, and Creative Partners

Twelve Ranks is a 12 × 12 chess variant for Windows. The current release offers
local two-player play and a built-in conventional computer opponent with varied
opening play that runs entirely offline. The project is licensed under the
Apache License 2.0 and is prepared for public development so that designers,
developers,
researchers, and responsible technology partners can help shape its future.

## Our current priority: visual designers

The project already has functional chess-piece artwork, but it needs a stronger,
more distinctive visual identity. Our highest-priority request is for designers
and illustrators who would like to redesign the complete board and piece set.

We are looking for a coordinated design system that covers:

- the board, squares, coordinates, selection states, legal moves, captures, and
  check indicators;
- the standard chess pieces;
- the Twelve Ranks **Minister**, **Chancellor**, and **Royal Guard** pawns;
- captured-piece and promotion artwork;
- scalable vector source files suitable for different display sizes;
- clear silhouettes, strong contrast, accessibility, and visual consistency.

Submitted artwork must be original work or use assets whose licenses permit
their inclusion and redistribution. Contributors must identify every external
asset, font, reference, and license used. A contribution is not guaranteed to
be accepted, and no paid engagement is created unless it is agreed separately
in writing.

Designers who are not familiar with Git can begin with the repository's
[artwork proposal form](https://github.com/VSDeveleoper/TwelveRanks/issues/new?template=artwork_proposal.yml),
share a portfolio or concept, and ask for help with the contribution workflow.

## Future opportunity: separate AI opponent partnership

A separate AI-service opponent is a future roadmap item; it is not included in
the current release. This future feature is distinct from the built-in
conventional computer opponent, which uses local game-search code and requires
no AI model or online API. We welcome conversations with AI
companies, research teams, and chess technology providers interested in
sponsoring or providing a suitable opponent service.

A responsible proposal should address:

- playing strength and adjustable difficulty;
- reliable and documented APIs;
- predictable availability, capacity, and long-term operating cost;
- player privacy, data retention, and whether submitted positions are used for
  training;
- security, abuse prevention, regional availability, and Microsoft Store
  compliance;
- graceful behavior when the service is offline or unavailable.

Any AI integration will require technical, privacy, licensing, cost, and
product review before it is accepted. The project will not promise a provider
exclusivity or transmit player data merely because an API is offered.

## Future opportunity: online multiplayer sponsorship

Online multiplayer is also a future roadmap item and is not part of the current
release. We welcome infrastructure companies and other partners interested in
sponsoring the services needed to operate it responsibly.

Proposals should cover hosting capacity, service availability, latency,
security, authentication, matchmaking, fair-play protections, moderation,
privacy, data location, incident response, maintenance, and sustainable cost.

Sponsors may propose reasonable commercial or technical terms. Every proposal
must be reviewed and agreed in writing. Sponsorship does not permit a partner to
override the open-source license, contributor rights, player safety or privacy,
Microsoft Store policies, fair-play requirements, or the maintainers' final
product and security decisions.

## How contributions will work on GitHub

1. Read the main README, this guide, the project license, the
   [asset license inventory](https://github.com/VSDeveleoper/TwelveRanks/blob/main/ASSET_LICENSES.md),
   and the contribution rules.
2. Before substantial work, open the appropriate issue form describing the
   design, feature, fix, or public partnership proposal.
3. Fork the repository to your own GitHub account.
4. Clone your fork to your computer and create a focused branch.
5. Make and verify your changes, including tests and documentation where
   applicable.
6. Commit the changes and push the branch to your fork.
7. Open a pull request against the main Twelve Ranks repository and explain the
   purpose, implementation, verification, licensing, and visual evidence.
8. Respond to review feedback. Maintainers may request revisions, decline a
   proposal, or close work that does not fit the project.

Contributors do not push directly to the main repository unless they are later
granted explicit maintainer access. A fork and pull request preserve review,
history, and accountability.

Unless a contributor conspicuously marks a submission as "Not a Contribution"
or a separate written agreement applies, contributions accepted into Twelve
Ranks are provided under the Apache License 2.0. This includes source code,
documentation, and artwork submitted through the project workflow.

## Contribution principles

Contributions should preserve:

- lawful and clearly documented intellectual-property rights;
- player privacy, security, and fair play;
- accessibility and support for all localized interfaces;
- deterministic game rules and reliable save data;
- transparent dependencies and maintainable source code;
- honest Store and project descriptions that distinguish shipped features from
  future plans.

Thank you for helping Twelve Ranks grow thoughtfully. Start at the
[Twelve Ranks GitHub repository](https://github.com/VSDeveleoper/TwelveRanks)
and choose the issue form that best matches the proposed contribution.
